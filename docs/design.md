# DSH 探索 / DSH Explore — 分支对话画布设计

插件名：中文「DSH 探索」，英文「DSH Explore」；页签与画布标题仍叫「无限探索」。包名（技术标识）为 `@local/dsh-explore`，仓库名 `dsh-explore`。

2026-11-10 起草 · 2026-11-11 按已落地的插件回写 · 状态：部分实现，见 §8

## 1. 意图

现在的对话是一条线：A→B→C。真实的思考不长这样——同一个回答上，人会同时想问好几件不同的事，而且这些事互不相干（C 问电费、D 问硬盘、E 问外网）。把想试的方向排队问，问完就压在历史里，也没法并排比较。

要做的是：**一个回答就是一个分岔口**。从任意节点再提一个问题，就长出新的子节点；这根枝条带着从根到它的完整来龙去脉继续往下走，枝条之间互不污染。整个结构是一棵树，能一眼看全，也能回到任何一个旧节点重新开枝。

## 2. 目标 / 非目标

目标

- 任意节点上追问，生成新的子节点，子节点的回答继承「根→该节点」的完整上下文。
- 一张画布上把整棵树画出来：节点是一问一答，连线表示父子。
- 优雅、克制：一个强调色，只用于「选中节点」和「根→选中」的路径高亮。
- 长大以后仍然可用：几十到上百节点时有折叠、搜索、自动排版、小地图。
- 回答是**真的**——流式、能调工具、能等审批、能被打断，和普通会话一模一样。

非目标（这一版不做）

- 不做「AI 自动把回答拆成分支」。分叉永远是用户主动开的。
- 不做节点内多轮对话（一个节点 = 一问一答）。要再聊，就在它下面开子节点。
- 不做导出成文档、分享链接、多人协作。
- 不替换 Chat 视图，也不改动现有会话的行为。

反目标（做到了也算失败）

- 卡片在流式输出时不断跳动、画布乱滚，导致读不下去。
- 分支的成本不可预期：用户点一下「追问」，结果悄悄跑了一条很贵的链路。
- 树里的节点和真实会话对不上（树上删了、会话还在；或者树上有一个、列表里冒出五个）。

## 3. 用起来是什么样

**画布**：无限画布，可拖拽、滚轮缩放（10%–200%）。顶部一条工具条：标题与节点/在跑计数、搜索框、缩放（−/百分比/+）、适应画布、**定位最新**。右下角小地图。画布只画**这一棵**树，它属于当前会话；空白处双击不新建根。

**定位最新**：工具条最右的蓝色按钮，一次点击做三件事——把从根到最新节点的祖先路径全部展开、把这张卡片居中（按卡片实际高度和被工具条占据的顶部空间计算）、选中它。最新按**创建时间**判定（`createdAt`，回落到本轮开始时间 `startedAt`），不是完成时间，所以并行几条枝同时跑、完成顺序打乱时也不会跳错。最新那张卡片头部有一个「最新」小徽标，随时能看出现在会跳去哪。没有节点时按钮置灰。

**按钮与主题**：所有按钮共用一个几何规格（32px 高、8px 圆角、图标+文字间距 6px），带 hover / active / `:focus-visible` 三态；颜色全部走主题 token（`--dsw-alias-*`），深色主题不用改代码，字体栈接 `--dsh-font-family-text` / `--dsh-font-family-code`。主按钮底色 `--dsw-alias-brand-primary` 会在深浅主题间反相（浅色近黑、深色近白），所以按钮文字必须用配套的 `--dsw-alias-label-primary-foreground`；Markdown 代码块、行内代码、阅读层遮罩与分隔线同样各有对应 token。`test/theme-tokens.cjs` 会拦下新写死的色值。卡片内动作是同一套的紧凑档（24px）与文字链档（`dsh-tree-link`）。

**节点卡片**：默认宽度 ~320px。卡内自上而下：序号徽标（A、B、C…）、问题（加粗，最多 3 行）、回答（正文，先显示约 6 行，点「展开全文」原位变高）、底部一排轻量动作（展开 / 复制 / 在此追问）。右上角一个 `+`，就是追问入口。

**追问**：点 `+` 或卡片底部「在此追问」→ 卡片下方就地长出一张输入卡（问题输入 + 发送），不弹窗、不跳页。回车发送后：新节点立刻出现（状态「思考中」，骨架屏），回答流式写进卡片，写完再做一次排版定位。

**同时跑几条**：几条枝可以同时流式。正在回答的卡片显示一条进度线和「停止」；工具条右侧显示「N 条分支在跑」，点它能在它们之间跳。等待审批或提问的分支如果不在视口里，在工具条上冒气泡，点一下把画布移过去——不在场的支不会悄悄卡住。

**进度可见**：正在回答的卡片里有一条常驻的进度行——转圈的指示器 + 「正在思考… / 正在调用 read / 正在输出…」+「第 N 步」+ 已用秒数；输出中的 token 以流式实时写进卡片的正文（Markdown 边写边渲染）。这些状态来自暂态事件 `assistant/live-chunk`（文本增量）、持久事件 `step/start`（步号）与 `tool/call` / `tool/result`（当前工具）。切到「无限探索」页签时，正在跑的那一轮会立刻显示当前进度和已产出的内容，不需要等这一轮结束。

**选中**：点卡片即选中。从根到它的一整条路径高亮（左侧 3px 竖线 + 连线变实），其余枝条降到 70% 不透明度。选中的卡片内嵌一个「继续问」输入框。

**折叠**：超过 2 层的枝条默认折叠成「⋯ N 个后代」的小圆点；点它展开。折叠状态按节点记住。

**搜索**：`Ctrl/Cmd+F` 或工具条搜索框，按问题与回答全文过滤；命中节点高亮，画布自动平移并把祖先路径展开。

**键盘**：`Enter` 发送，`Shift+Enter` 换行，`Esc` 取消输入，`Tab` 在兄弟节点间跳，`Delete` 删除节点（带确认）。

**删除**：只能删叶子或整棵子树（大子树二次确认）。删子树 = 归档对应的会话，不物理删除。

## 4. 数据模型

树不是一份独立数据：内容是**会话日志的投影**，插件只在浏览器里记一层叠加层，外加一份随时可以重建的投影快照。

- **一个节点 = 会话里的一轮问答**：问题是一条 user 消息，回答是紧随它的 assistant 消息。根会话自己的多轮天然连成一条链——线性对话是退化成一条线的树。**只有开新枝时才 fork 新会话**，所以「100 个节点」不等于「100 个会话」，多出来的会话数只等于分支数。
- **父子边不在宿主里**：`fork({ sessionId, atSeq })` 只记录 `inheritedEventCount`（前缀长度）和一条 `session/end-seed`（`data.inherited === true`），**不写 `parentSession`**。所以「谁是父」必须由插件自己的索引记住：`子 sessionId → { 树根 sessionId, 父节点 id }`，存在 `localStorage`。
- **分支会话要有基线**：fork 出来的会话开头带着父会话的前缀，读事件时得跳过 seed 之前的部分（插件记 `baseSeq`，没有就退回 seed 的 seq），否则父会话的回答会被当成这根枝的回答。
- **叠加层**：父子索引、折叠状态、删除墓碑、节点投影快照。卡片高度是运行时量的，不落盘；内容和状态以日志为准，快照只是为了打开得快。
- **删除**：会话日志不能截断，所以删除只能是叠加层里的墓碑（`hidden` 映射），节点和它的后代一起从画布上消失。被删枝条独占的 fork 会话用 DSH 的归档收起（根会话和仍有可见节点的会话不动）；DSH 的归档不级联，所以「恢复」要按记住的清单逐个解档。删掉的会话内容仍然在，只是不在列表和画布上。

于是几种情况规则一致：

- 打开一个已经有 5 轮的旧会话 → 树上直接显示 5 个节点连成链，不需要先「录一遍」。
- 在 Chat 里继续聊某一枝 → 该会话多一轮 → 树上多一个节点，父节点自动接上。
- 重试 / 重新生成 → 卡片更新成新回答；已经从旧回答分出去的子枝依然有效（它们引用的前缀没变）。
- 在 DSH 里别处 fork 出来的会话 → 插件认不出来，打开它时会被当成一棵新树的根（见 §9）。

```
fork(父节点.sessionId, atSeq = 父节点回答的 seq) → 子 sessionId
prompt(子 sessionId, 新问题)                     → 流式回答
```

「带着 A→B 往下走」不是拼 prompt 拼出来的，而是分叉天然带过来的前缀。工具、审批、流式、取消、重试全部复用现有 agent loop。

树的归属：一棵树 = 一个「根会话 + 它的全部后代分叉」。根节点是该会话的第一次提问。视图挂在会话上，切到一个分叉会话时靠索引找到树根，所以看到的还是整棵树。

## 5. 怎么接进 DSH

已经有一个手写插件：仓库根目录本身（`@local/dsh-explore`），以 `link:` 依赖（符号链接）装进桌面 profile，宿主把它当 lazy-CJS 的 `client.js` 直接供给页面，没有打包器；文件一改，宿主按 mtime/size 热替换，连页面都不用刷。它只注册一个 `conversation.view`：id `tree`、order 5、label 无限探索。

- **客户端不能直接调模型，只能通过会话**。可用的动作是 `prompt(content, mode)` 与 `cancel()`；token 以暂态事件 `assistant/live-chunk`（`data.chunk.type === 'text-delta'`）到客户端，落定后是持久的 `assistant/message`，收尾是 `turn/end`。宿主侧的 `agent/assistant-stream` 客户端插件看不到，别指望它。
- `ctx.sessions.fork({ sessionId, atSeq })` 从精确前缀分叉：`atSeq` 是**包含该 seq** 的事件边界，子会话复制整段事件前缀（不只是消息），随后补 `session/end-seed`；允许在一轮尚未结束时 fork，父会话本身不受影响。血统问题见 §4。
- **读历史**：会话绑定上有一个事件窗口（`entries`、`hasMore`），窗口不够长就 `loadOlder()`。要读一个当前没在看的会话（某根枝），先把它 retain 住，拿到绑定再订阅。
- **持久化**：内容本体在会话日志；父子和视图状态在 `localStorage`，按树根分区，父子索引单独一个键。
- **已知限制**：手写包加不了新的 Remote/RPC 命名空间，跨端逻辑只能走已有的 `sessions` 或宿主 `/api` 路由。本设计不需要新 RPC。

## 6. 规模：几十到上百节点

- **自动排版（已实现）**：同层子树紧凑排列、父节点居中于子节点；画布平移只动 transform，不改布局。手动拖节点把位置钉住还没做。
- **折叠（已实现）**：默认只展开到第 2 层，更深的枝条收成「⋯ N 个后代」计数点，点开即展开且记住；展开过的枝不会再自己收回去。
- **虚拟化（已实现）**：节点超过 40 个时只渲染视口内的卡片（外加一屏余量），画布本体只有一层 transform。
- **搜索 + 小地图（已实现）**：工具条搜索框按问题与回答全文过滤，回车逐个跳；右下角小地图点哪去哪。定位与全局感靠这两样，不靠缩放到底。
- **并发下的排版**：正在回答的卡片高度随流式增长、连续重排还没收住；设计是先钉住位置，这一枝写完再整体排一次，避免几条枝同时流式时画面抖动。
- **成本可见（已实现）**：卡片角上标这一轮的耗时与 token。耗时 = 该轮 `turn/end.time` − `turn/start.time`；token 取该轮**最后一步** `assistant/message` 的 `usage.totalTokens`——一轮有 N 步、每步都重复整段上下文，把各步相加会重复计费（实测 10×–62×）；命中缓存的 token 单列在悬停提示里，不计进输入合计。没有 `turn/end` 的轮次标为进行中，只量到窗口末尾。

## 7. 取舍

- **一根新枝 = 一个真实会话**。根会话里的多轮自己连成一条链，不额外开会话；只有从某个节点分出去的新枝才 fork。代价是每根枝都会在会话列表里多一条（插件会把它改名成 `⟂ 父问题 · 新问题`），而删枝只能归档这个会话；DSH 的归档不级联，恢复得逐条来。
- **上下文继承是天然的**（fork 带前缀），也意味着深处节点的上下文会很长，越深的枝越贵；这是「从 B 出发」的必然代价。
- 卡片内嵌回答（方案 1）在 100 节点时会很大，靠折叠 + 只渲染视口来对冲。
- **没有 `parentSession`** 意味着树里那根连线是插件自己记的，而且只记在这台机器的这个浏览器里。换浏览器、清站点数据、换 profile，树就**平掉**：每个会话自己那条链还在，但枝从根上断了，也没法知道哪些会话属于同一棵树。

## 8. 默认（兼状态表）

§3 写的是做完后的样子，这一节逐条标现在的状态。

1. 树视图长在会话里，作为 Chat / Trajectory 旁边的第三个页签；切到一个分叉会话时，视图解析到它最顶端的祖先，再选中当前节点。—— 已实现（页签 id `tree`、order 5、label 树；解析树根有了，自动选中当前节点还没有）
2. 一个节点 = 一问一答；继续聊就开子节点。—— 已实现
3. 卡片内嵌回答，先显示几行可展开。—— 已实现（约 7 行 / 260 字后折起）
4. 默认展开 2 层，其余折叠。—— 已实现（深度 ≥ 2 且带子节点默认折叠，用户展开过就记住）
5. **节点是会话的投影，不是独立记录**（见 §4）。在 Chat 里继续聊，树上就会长出节点；这是特性，不是 bug。—— 已实现（投影快照缓存在 `localStorage`，内容仍以日志为准）
6. **只有回答完成的节点能开新枝**。失败或被中止的节点给「重试」，不从半截回答出发。—— 已实现（`+` 只在完成且有回答 seq 时出现；「重试」还没做）
7. 分叉是真实会话；若它们污染会话列表，就归档隐藏。—— 已实现（开枝时自动改名为 `⟂ 父问题 · 新问题` 便于辨认；不做自动归档，避免会话在列表里凭空消失）
8. 用 DSH 当前选中的模型与权限设置，不额外提供模型选择器。—— 已实现（分支就是普通会话）
9. 删除 = 归档子树，可恢复。—— 已实现（墓碑叠加层 + 归档该子树独占的 fork 会话；工具栏「已隐藏 N 个 · 恢复」逐个解档）
10. 不做导出与分享（这一版）。—— 未做（非目标，见 §2）
11. **几枝可以同时跑**；每枝单独停止，全局显示在跑的分支数。—— 已实现
12. **画布挂在会话上**，是第三个页签；不做「装好几棵树的本子」。—— 已实现（本子见 §9）

## 9. 已知缺口

- **导出与分享**：没有。树只活在这台机器的这个浏览器里，拿不出去，也没法给别人看。
- **跨会话的本子**：没有。视图绑定当前会话的树根，没有「把几棵树摆在一起」的地方。
- **不在视口里的分支**：审批、提问、出错只体现在卡片状态和工具条的运行计数上；卡片不在视口时不会主动冒出来提醒。
- **别处的分叉**：DSH 里在插件之外 fork 出来的会话，插件发现不了，打开时会被当成新树的根，血统也接不回去。
